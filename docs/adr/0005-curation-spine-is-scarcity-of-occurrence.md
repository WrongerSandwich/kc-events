# Curation is structured by scarcity of occurrence, not a blended interest score

Each event gets a recurrence class (one-off, limited run, recurring) derived deterministically from page evidence. Only one-offs and limited runs are eligible for the don't-miss flag, which the model assigns with a stated why-line. Recurring events are never on the don't-miss list. The flag and why-line are re-judged only when an event's underlying facts (date, venue, status) change, never on every run. Every run does clean stray JSON punctuation off stored why-lines without a model call; that is not a re-judgment, though a flag whose why-line cleans to nothing stops being a flag. We rejected a blended "interest score" because it is opaque, unstable between runs, and reads as arbitrary on a taste-neutral public site. The model's judgment lives inside the structure (which one-offs are notable, and why), not over it.

**Amended (#79):** the underlying facts are title, date, venue, and status. A title or venue that changes only in case or punctuation is unchanged. A date is compared as a calendar date, and by its time of day only when both readings carry one, so a page that gives no time where another gave one, or doors where another gave the show, no longer re-judges every run. When two records fold as one event, the kept record carries the judgment of whichever of the pair was judged later; a recurring record takes none. Curation sees the event's description, when extraction wrote one, alongside the title, so an unfamiliar title is not by itself a reason to withhold a flag.
