# An event's own page is a link beside its primary page, not a second primary page

Nearly every event the job published through 2026-10-06 sent the reader to the list it was read from: the venue's calendar, or a list page discovery found. The lists do link each show's own page, but the page text handed to the extraction model had every `<a href>` stripped, so the rule telling it to prefer a dedicated page could never fire; and had it fired, cite-or-drop (ADR 0002) would have held the event unverified, since the dedicated page was never fetched, while identity (ADR 0007) would have made it a new record.

The primary page keeps both of its jobs, the page the date and venue were read from and the key the event is known by, and gains a companion: the event's own page, `eventUrl`, which is only where the site sends the reader. The page text keeps each followable link as a number after its text; the model names an event's page by number; the job resolves the number against the page's own anchors, so the model never writes a URL. The event page is never fetched and plays no part in verifying; a re-reading replaces or drops it like any other field, without counting as a change for curation.

We chose this over the two-hop alternative, following every list link and making each event's own page its primary page, which ADR 0001 describes more literally. Two-hop costs about ten times the fetches and model calls a run makes now, is slower, reads event pages that often restate less than the list (a ticket page may name no venue), and changes every active event's identity. It stays open as a per-source option for a source whose list page cannot cite date and venue; the links this decision surfaces are what it would follow.

**Amended (#75):** the event's own page must be on the primary page's site (its registrable domain) or on one of the ticketing platforms the config lists (`discovery.platformHosts`). A link anywhere else resolves to nothing and the event sends the reader to its primary page. The link is the one place the site sends a reader somewhere it has not read, so where it may go is decided by who chose it: the venue, on its own site, or a platform everyone sells through, never a page the job found. The dataset schema refuses an own page anywhere else, taking the platform list from the config so the two cannot drift; the committed dataset was brought under the rule by hand in the same change, dropping the forty-seven links that broke it, nearly all from listing sites since made aggregators.

**Amended (#123):** one opt-in exception to "never fetched", the per-source two-hop held open above, narrowed to the time. A registry source flagged `readEventPages` (the Lied Center, whose list gives every event's date and no time) has the own page of each event its list dated without a time, starting from today through the horizon, fetched the source's way and read by a small call of its own (`prompts/event-page-rules.md`) for that event's date and time. A time on the list's date, quoted from the own page, found there, and given in the quote itself (not a quote of the date alone), joins the start, and the quote is kept beside the date and venue quotes with the page it came from (`evidence.time`, which the schema allows only on a timed start and only from the event's own page). The list stays the primary page: identity, standing, the date and venue quotes, and re-verification do not move. An own page giving another date is left for a person and reported; any failure, fetch or model, costs only the time, never a strike or an outage. Each source's reads get a line in the report, and every call goes through the spend cap and the report's call list. A time once read is kept, not re-read each run: while a re-reading of the list gives the same date with no time and the same own page, the stored time and its quote stand and the page is not fetched again; a new date, a time of the list's own, or another own page drops it, and the next run reads again. A re-read each run would cost a call per event per week to learn what the list, by not changing, already says has not changed.

**Amended (#133):** a second exception, for the picks. After curation, every active don't-miss event with an own page and a date from today through the horizon has that page read once, the same way and under the same rules document, now asking for the price and the age limit as the page states them (each with its quote, kept under `evidence.price` and `evidence.ages` beside `evidence.time`, which the schema allows only from the event's own page), a fuller description when the stored one is absent or a list line's length, and the time as above. A quote must be on the page and contain the value it is given for; a value without one is dropped and reported, and a read giving another date takes nothing. The read is recorded (`ownPageRead`: the page and the run's date) and kept, with what it gave, while a re-reading of the list gives the same date and the same own page, so a pick's page is read once per date and own page, not each run; the picks are a dozen or so a week, so the reads are too. A pick a flagged source's own-page time already read this run is not read twice. The picks' reads get their own line in the report ("Picks"), counting the reads kept from an earlier run.

**Amended (#254):** the two exceptions become one pass for every upcoming event. After re-verification and before curation, every active event with an own page whose span covers a day from today through the horizon has that page read as the picks' are, under the same rules and the same keep-while-unchanged record, nearest start first and at most `ownPageReadsPerRun` a run (150), the rest left for the next. Curation then judges from the fuller description; times, prices and age limits reach the whole set, not a dozen picks; the per-source `readEventPages` flag is retired, its case covered. The 2026-10-31 audit found 297 of 318 upcoming own pages never read and 157 events with no description, and the reads cost about $0.002 each, so about $0.10 a week once the first pass is done. A host whose robots.txt refuses one own page is not fetched again that run. The picks' pass after curation stays, for a pick the ceiling left.
