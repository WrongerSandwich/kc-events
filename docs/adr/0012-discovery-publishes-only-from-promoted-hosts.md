# A discovered host's events are held until the host is promoted

Through 2026-10-10 any page the discovery lane reached was a primary source with the same authority as a registry calendar: a page the search ranked, or one of the first links off an aggregator page, published to the site straight from extraction. The registry was the primary lane in name only. In the 2026-10-09 dataset about nine percent of active events had been read from listing sites nobody had looked at, and they accounted for most duplicate clusters, the venue-is-"Downtown" records, and a third of the unverified. The same mechanism is the site's one real exposure: a plausible page, reachable by search, publishes an event with its own link-out, and can be flagged don't-miss, since a famous name at a small room is what curation rewards.

Discovery now finds; a person admits. A new event whose primary page is on a host that is neither a registry source nor a ticketing platform is stored unverified and marked held for promotion, and never rendered, until the host is promoted into the registry by hand. Promotion stays what it was, a suggestion in the run report after a host has yielded events in two runs; acting on it releases the held events on the next run, so nothing found is lost, only delayed by about a week. A host the registry excludes is never followed by discovery at all: the exclusion was a decision about the host, not about one lane. The site therefore only ever shows events from a page a person has looked at, which is what the proposal meant by the registry being the primary lane.

Two alternatives were considered. Publishing discovered events to the explorer while keeping them off the don't-miss list would have kept the explorer "complete" but left the wrong-venue and duplicate records on the site, and the editorial surface is not the only one a reader trusts. Accepting the risk, relying on matching rules, the evidence check, and a hand-grown list of aggregator hosts, is what the first six weeks did; the aggregator list grew by thirty hosts and the listing-site records kept coming. The cost of holding is that discovery adds nothing to the site by itself; the growth of the registry is the mitigation, and the run report's suggestions are its queue.
