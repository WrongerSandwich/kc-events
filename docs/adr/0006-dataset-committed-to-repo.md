# The dataset and run reports are committed back to the repo by each run

The research job is incremental, so state must persist between weekly runs. We commit `events.json`, the registry, and each run's report back to this repo from the job itself, rather than keeping state only in a deploy artifact or an external store. Git history is then the audit trail for every add, update, and expiry, which is what grading wrong dates needs, and the weekly commit is also the repository activity that stops GitHub from auto-disabling a public repo's scheduled workflows after 60 days of inactivity. The cost is a growing history of a few hundred KB a week, accepted.

**Amended (#22, ADR 0010):** the 60-day note no longer applies; the workflow has no schedule to disable, and the weekly commit now comes from a home machine.

**Amended (#82):** the history grew faster than "a few hundred KB a week" foresaw (718 KB to 1.05 MB in four days, a third of it expired records with full evidence), and each weekly commit rewrites the whole file. A run now moves an expired record whose last day and last change are both more than eight weeks back into `data/archive/<year>.json`, committed with the run; the live file is what the next run loads, and nothing reads the archive to run. A record that no reading ever verified and no lane has sighted for four runs expires `stale`, and so archives in turn. The state the dataset carries forgets too: a discovery host unseen for eight runs with discovery on, any aggregator, platform or registry host, and a registry source's failure count once the source leaves the registry. A verified re-reading that differs from what is stored only in whitespace or punctuation keeps the stored text, so the weekly diff is what changed.
