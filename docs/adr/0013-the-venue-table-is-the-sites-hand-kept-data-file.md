# The venue table is the site's own hand-kept data file

A venue page (#137) needs what no page the job reads gives reliably: the venue's street address, its position, and its own site. That is hand-kept data, and it needed a home. The job already keeps one hand-kept list about venues, `venueAliases` in `research.config.yaml`, so a section beside it was the obvious candidate.

The table is `data/venues.yaml` instead, one row per venue, read by the site's build and nothing else. The research job never reads an address or a position, so putting them in its config would make an address fix an edit to the run's settings, reviewed as one, and would put a site-only list in the file every run parses. `venueAliases` stays in the config because the job uses it to match events; the table keys on the display name that list produces (the venue's alias key, or the name as pages give it when it has none) and adds nothing to matching. Kept beside `data/events.json` and `data/registry.yaml`, it is in the place a person looks for the job's hand-kept data, and like them it is committed.

The build holds the two lists together: a row keyed on an alias (it names the key to use), on a name no record in the dataset and no `venueAliases` entry has, or two rows for one page fail the build with the row named. A page's slug is derived from the name, never stored: a result row in the explorer links its venue's page with nothing added to the event data the explorer carries, so the slug cannot be overridden, and renaming a venue's display name moves its page.

**How a row is added.** Add the venue's display name exactly as the site shows it (if the venue should go by another name, or its rooms be merged into it, change `venueAliases` first), its address on one line as `<street>, <city>, <MO|KS> <ZIP>`, and optionally `lat` and `lng` (both or neither; look the place up, as on OpenStreetMap, never from memory) and `url`, the venue's own site. A district with no one street address (the Crossroads) gives a position instead of an address; a row needs one or the other. Check the row by opening its page's map link. A venue with no row still has a page, with its events and neighborhood alone.
